# Moxa 風險盡職調查與管理平台（人權版）

一個純前端網頁（不需編譯）＋ Supabase 雲端資料庫的工具。前台繁中／簡中／英文三語切換。

## 功能一覽

| 區塊 | 前台 | 後台（總管理者） |
|---|---|---|
| 人權盡職調查 | 矩陣式填答（基本資料 → 一次評全部發生機率 → 一次評全部嚴重程度 → 補充說明 → 預覽個人矩陣後送出）、草稿自動儲存、個資告知；上傳 Microsoft Forms 結果 Excel 自動辨識欄位並預覽後匯入 | 問卷文字／題目／量表編輯（三語）、調查週期與受邀人數、填答資料檢視、數值調整（保留原始值與調整原因）、刪除、匯出 |
| 人權風險管理 | 風險儀表板（MHQ／RBU／各區域、填答者篩選、平均／中位數／最大值、疊圖比較、點選議題看分布與質化回饋）、風險矩陣匯出 Excel（可編輯：色塊矩陣＋原生散佈圖）／PNG／SVG、措施盤點與建議（依關注程度給建議、集團既有措施自動標示、急迫性計算）、行動計畫、跨區域總覽（管理者） | 組織與區域、各區域密碼、建議措施庫、矩陣分區（逐格設定）與急迫性權重、前台文字三語覆寫（可匯出／匯入翻譯 Excel）、稽核日誌、備份還原 |

**登入與權限**：共 5 個專屬登入頁（MAT、MCN、MUS、MEU、總管理者），網址為 `index.html#/login/MAT` 等，密碼由總管理者在 後台 › 組織與密碼 設定（該頁也列出 5 個網址可直接複製寄給各區域）。區域 HR 主管登入後只會看到 MHQ、RBU 整體、自己的區域；其他區域只以「RBU 其他區域」的匿名分數併入 RBU 整體。總管理者可看全部。

> ⚠️ 依決定採**純前端密碼驗證**：密碼以雜湊值存在資料庫、在瀏覽器比對，區域可見範圍也由網頁控制。懂技術的人可繞過網頁直接讀寫資料庫（含填答者姓名、Email）。適合內部使用；若日後要對外或需符合 GDPR 稽核，建議改為伺服器端驗證。

**急迫性** = 風險權重（高 1.0／中 0.6）×（1 − 措施覆蓋率）× 100。覆蓋率：已實施／集團已涵蓋 = 1、部分實施 = 0.5、未盤點／計畫採行 = 0、不適用不計；高度關注加強措施權重 1.5。≥60 立即處理、≥40 優先處理、≥20 計畫改善，其餘持續維持。全部可在後台調整。

## 先試用（示範模式）

`js/config.js` 的 `supabaseUrl` 留空即為示範模式，資料只存在該瀏覽器。用 Edge 或 Chrome 直接開啟 `index.html` 即可試用（需連網以載入 CDN 函式庫）；若瀏覽器限制本機檔案，改用任一本機網頁伺服器開啟資料夾。

初始密碼為「代碼#2026」：總管理者 `ADMIN#2026`；各區域 `MAT#2026`、`MCN#2026`、`MUS#2026`、`MEU#2026`。正式上線後也是同一組初始密碼，**請第一次登入就到後台更改**。

示範模式已內建 2025 MHQ 調查結果（依決定沿用為 2026 MHQ 資料，只有 HRBP／RM 群組平均，無個資）。RBU 的 32 筆填答請以總管理者登入後，在「人權盡職調查 › 匯入 Forms 結果」上傳 `2026 Moxa 人權盡職調查 (for RBU)(1-32).xlsx`。

## 正式上線（Supabase）

1. 到 supabase.com 建立專案（建議選 Tokyo 或 Singapore 區域）。
2. **SQL Editor** 貼上並執行 `supabase/schema.sql`（建立資料表與存取規則，並寫入 2026 週期與 2025 MHQ 資料；可重複執行）。不需要建立任何 Supabase 帳號。
3. **Project Settings › API** 複製 Project URL 與 anon public key，填入 `js/config.js`。**service_role key 絕不可放進前端**。
4. 部署整個資料夾到任何靜態網站主機（擇一）：Azure Static Web Apps（建議，可與 IT 協調公司網域）、GitHub Pages、Netlify、或公司內部 IIS。
5. 開啟 `#/login/ADMIN`，以 `ADMIN#2026` 登入 › 後台 › 組織與密碼：立即更改 5 組密碼，並複製各區域網址寄給 HR 主管。
6. 後台確認問卷、週期（開放填答）、受邀人數；到「匯入 Forms 結果」上傳 RBU Excel。

新增區域（例如日本）：後台 › 組織與密碼 新增區域代碼並設定密碼 → 後台 › 問卷內容 的 regionOptions 加上該代碼。

## 換成其他主題（財務、資安、企業風險…）

整個工具以「主題設定」驅動：題目、量表定義、矩陣分區、三個管理面向、建議措施庫、組織層級全部在後台編輯，存在 `app_config`。要另開一個主題，最簡單的做法是：複製整個資料夾、建立新的 Supabase 專案、在後台改寫題目與建議庫即可，不需改程式。程式中的預設內容在 `js/seed.js`（題目／量表／分區）與 `js/recs.js`（建議庫）。

## 檔案結構

```
index.html            入口
css/app.css           樣式
js/config.js          部署設定（Supabase URL / key）
js/i18n.js            介面文字三語（後台可覆寫）
js/seed.js            預設主題：問卷原文、量表、分區、2025 MHQ 資料
js/recs.js            建議措施庫（167 條，含 32 條取自 2025 永續報告書的集團既有措施）
js/data.js            資料層（示範模式 / Supabase）
js/matrix.js          統計、風險矩陣 SVG、PNG/SVG/Excel 匯出
js/xlsxw.js           Excel 產生器（含原生圖表）
js/forms.js           Microsoft Forms Excel 解析
js/app-*.js, app.js   畫面
supabase/schema.sql   資料庫結構與權限
```

## 注意事項

- 問卷繁中文字依 PDF 原文；簡中與英文為初稿，可在 後台 › 問卷內容 修改。
- Forms 匯入以「電子郵件」判斷重複（同一人重複匯入會更新而非新增）。
- 填答者姓名、Email 屬個資（MEU 適用 GDPR）。請勿把含個資的 Excel 或備份 JSON 放進網站資料夾。
- 外部函式庫由 CDN 載入（Vue 3.4.38、supabase-js 2.45.4、SheetJS 0.18.5、JSZip 3.10.1），若公司網路封鎖 CDN，可下載到 `js/vendor/` 並修改 index.html 路徑。
